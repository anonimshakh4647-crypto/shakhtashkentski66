PowerShell nima va qanday ochiladi?

Buyruqlar qatori nima va nega kerak

PowerShell — Microsoft tomonidan yaratilgan, Windows'da (va endi Linux/macOS'da ham) ishlaydigan zamonaviy buyruqlar qatori (konsol) va skript tili. Oddiy "CMD" dan farqi: PowerShell'da hamma narsa matn emas, balki haqiqiy obyekt (masalan, fayl, jarayon, xizmat) sifatida ishlaydi — bu esa ma'lumotni filtrlash, saralash va qayta ishlashni ancha osonlashtiradi.

PowerShell orqali siz: fayllarni ommaviy nomlash, dasturlarni avtomatik o'rnatish, tizim holatini tekshirish, internetdan ma'lumot olish va hatto butun ishni avtomatlashtirish skriptlarini yoza olasiz.

Qanday ochiladi:

  • Win tugmasini bosib, PowerShell deb yozing va Enter bosing.
  • Windows 11'da bu endi Windows Terminal ichida ochiladi (zamonaviy, tablar bilan).
  • ISE (Integrated Scripting Environment) — eski, lekin skript yozish uchun qulay grafik muhit (`powershell_ise.exe`).
  • Zamonaviy tavsiya: VS Code + "PowerShell" kengaytmasi — eng qulay yozish muhiti.
 PowerShell
PS C:\> Write-Host "Salom, Dunyo!"
Salom, Dunyo!
💡
Yuqoridagi birinchi buyruq — Write-Host — ekranga matn chiqaradi. Buni o'zingiz PowerShell'ga yozib, Enter bosib sinab ko'ring!
Savol: PowerShell bilan CMD orasidagi asosiy farq nima?
Javob: PowerShell'da ma'lumotlar obyekt sifatida uzatiladi (xossalari va metodlari bilan), CMD'da esa hammasi oddiy matn sifatida ishlaydi. Shu sababli PowerShell'da ma'lumotni saralash/filtrlash ancha oson.
1

Cmdlet, Get-Help, Get-Command

Buyruqlarni qanday topish va tushunish mumkin

PowerShell buyruqlari cmdlet (kamandlet) deyiladi va doim Fe'l-Ot (Verb-Noun) shaklida yoziladi: Get-Process, Stop-Service, New-Item. Fe'l nima qilishni (Get=olish, Set=o'rnatish, New=yaratish, Remove=o'chirish), ot esa nima ustida ishlashni bildiradi.

 Eng muhim 3 ta yordamchi buyruq
PS C:\> Get-Command *process*    # "process" so'zi bor barcha buyruqlarni topadi
PS C:\> Get-Help Get-Process -Full  # buyruq haqida to'liq qo'llanma
PS C:\> Get-Process | Get-Member   # natijaning qanday xossalari borligini ko'rsatadi

Birinchi marta Get-Help ishlatganda, PowerShell internetdan to'liq qo'llanmalarni yuklab olishni so'raydi — buning uchun Update-Help buyrug'ini admin huquqida bir marta ishga tushiring.

ℹ️
Qisqartmalar (alias): ls, dir, gci — bularning barchasi aslida Get-ChildItem ning taxallusi. Yozishni tezlashtirish uchun qulay, lekin skript yozganda to'liq nomdan foydalanish tavsiya etiladi (tushunarliroq bo'ladi).
Savol: "Barcha xizmat (service) bilan bog'liq buyruqlarni" qanday topasiz?
Javob: Get-Command *service* — yulduzcha (*) "istalgan matn" degani, shuning uchun nomida "service" so'zi bor barcha buyruqlarni ko'rsatadi.

3

O'zgaruvchilar va ma'lumot turlari

Qiymatlarni saqlash va ishlatish

O'zgaruvchi nomi har doim $ belgisi bilan boshlanadi. PowerShell turni o'zi aniqlaydi (dynamic typing), lekin xohlasangiz turni qat'iy belgilash ham mumkin.

 Misol
PS C:\> $ism = "Alisher"
PS C:\> $yosh = 21
PS C:\> $narx = 19.99
PS C:\> $faol = $true
PS C:\> [int]$son = "42"          # turni qat'iy belgilash
PS C:\> "Salom, $ism! Sen $yosh yoshdasan."   # qo'shtirnoq ichida o'zgaruvchi avtomatik almashadi
Salom, Alisher! Sen 21 yoshdasan.
ℹ️
Oddiy qo'shtirnoq '...' ichida o'zgaruvchi almashtirilmaydi, lekin juft qo'shtirnoq "..." ichida almashtiriladi. Bu — eng ko'p uchraydigan boshlang'ich xato!
Savol: $x = 5; '$x soat' deb yozsangiz, natija nima bo'ladi?
Javob: aynan $x soat deb chiqadi (5 emas) — chunki oddiy qo'shtirnoqda o'zgaruvchi almashtirilmaydi. Buning o'rniga "$x soat" yozish kerak edi.

Operatorlar

Solishtirish, mantiqiy va arifmetik amallar

PowerShell'da solishtirish operatorlari > yoki < emas, harf bilan yoziladi (chunki > fayl yozishni bildiradi):

OperatorMa'nosi
-eqteng (equal)
-neteng emas
-gt / -ltkatta / kichik
-ge / -lekatta-yoki-teng / kichik-yoki-teng
-likenaqshga mos keladi (* bilan)
-matchregex'ga mos keladi
-and / -or / -notmantiqiy VA / YOKI / EMAS
 Misol
PS C:\> 10 -gt 5
True
PS C:\> "Shaxzod" -like "Sha*"
True
PS C:\> ($yosh -ge 18) -and ($faol -eq $true)
True
Savol: Nega "5 > 3" PowerShell'da kutilgandek ishlamaydi?
Javob: > belgisi PowerShell'da "natijani faylga yoz" degani (masalan dir > natija.txt). Solishtirish uchun -gt ishlatiladi: 5 -gt 3.

Massiv va Hashtable

Bir nechta qiymatni birga saqlash

Massiv (array) — tartiblangan ro'yxat. Hashtable — kalit-qiymat juftliklari (lug'at kabi).

 Massiv
PS C:\> $mevalar = "Olma","Nok","Uzum"
PS C:\> $mevalar[0]
Olma
PS C:\> $mevalar += "Anor"     # qo'shish
PS C:\> $mevalar.Count
4
 Hashtable
PS C:\> $foydalanuvchi = @{ Ism = "Dilnoza"; Yosh = 25; Shahar = "Toshkent" }
PS C:\> $foydalanuvchi.Ism
Dilnoza
PS C:\> $foydalanuvchi["Yosh"] = 26   # qiymatni yangilash
Savol: Massiv bilan Hashtable'ning asosiy farqi nima?
Javob: massivda elementlarga tartib raqami (index: 0, 1, 2...) orqali murojaat qilinadi, hashtable'da esa har bir qiymat o'z nomi (kaliti) orqali olinadi.

Shartli operatorlar — if, elseif, switch

Dasturga "qaror qabul qilish"ni o'rgatish
 if / elseif / else
PS C:\> $yosh = 17
if ($yosh -ge 18) {
    Write-Host "Kattasiz"
} elseif ($yosh -ge 13) {
    Write-Host "O'smirsiz"
} else {
    Write-Host "Bolasiz"
}
O'smirsiz
 switch — ko'p shart bo'lganda qulayroq
$kun = "Shanba"
switch ($kun) {
    "Yakshanba" { Write-Host "Dam olish" }
    "Shanba"    { Write-Host "Dam olish" }
    default     { Write-Host "Ish kuni" }
}
Dam olish
Savol: Bir xil natijani bir nechta qiymat uchun tekshirishda (masalan, 5 xil kun nomi) if yoki switch — qaysi biri tozaroq ko'rinadi?
Javob: switch — ko'p variantli tekshiruvlarda if/elseif zanjiridan ko'ra ancha qisqa va o'qilishi oson bo'ladi.

Tsikllar — for, foreach, while

Amalni avtomatik takrorlash
 foreach — ro'yxat bo'ylab yurish
$mevalar = "Olma","Nok","Uzum"
foreach ($meva in $mevalar) {
    Write-Host "Men $meva yoqtiraman"
}
 for — aniq sondagi takrorlash
for ($i = 1; $i -le 5; $i++) {
    Write-Host "Raqam: $i"
}
 while — shart to'g'ri bo'lguncha
$son = 1
while ($son -le 3) {
    Write-Host "Soniya $son"
    $son++
}
Savol: Agar shart boshidanoq noto'g'ri bo'lsa, while tsikli nechi marta ishlaydi?
Javob: 0 marta — while shartni HAR safar tsikl boshida tekshiradi, agar u noto'g'ri bo'lsa, ichidagi kod umuman bajarilmaydi.

Funksiyalar

Kodni qayta ishlatish uchun bo'laklarga bo'lish
 Oddiy funksiya
function Salomlash {
    param(
        [string]$Ism = "Mehmon",
        [int]$Yosh
    )
    Write-Host "Salom, $Ism! Sen $Yosh yoshdasan."
}

Salomlash -Ism "Kamola" -Yosh 23
Salom, Kamola! Sen 23 yoshdasan.
 Qiymat qaytaruvchi funksiya
function Kvadrat($son) {
    return $son * $son
}
$natija = Kvadrat 7
Write-Host $natija
49
💡
Parametr nomini ko'rsatib chaqirish (-Ism "Kamola") kod o'qilishini ancha oshiradi — ayniqsa funksiyada bir nechta parametr bo'lsa.
Savol: Funksiyadan qiymat "qaytarish" uchun qaysi kalit so'z ishlatiladi?
Javob: return — lekin PowerShell'da funksiya ichida chiqarilgan HAR QANDAY natija (hatto return'siz ham) avtomatik "qaytariladi", shuning uchun bu xususiyatga ehtiyot bo'lish kerak.

Pipeline va obyektlar bilan ishlash

PowerShell'ning eng kuchli qismi

Pipeline (| belgisi) bir buyruqning natijasini keyingisiga obyekt sifatida uzatadi. Uchta eng muhim "filtr" cmdlet:

CmdletVazifasi
Where-ObjectShartga mos elementlarni tanlaydi (filtr)
Sort-ObjectSaralaydi
Select-ObjectFaqat kerakli ustun/sonni tanlaydi
ForEach-ObjectHar bir elementga amal bajaradi
 Haqiqiy misol
PS C:\> Get-Process |
    Where-Object { $_.CPU -gt 10 } |
    Sort-Object CPU -Descending |
    Select-Object -First 5 Name, CPU

Bu bitta qator — "barcha jarayonlarni olish → CPU 10 dan ko'p bo'lganlarini tanlash → CPU bo'yicha kamayish tartibida saralash → eng yuqori 5 tasining Nom va CPU'sini ko'rsatish" degani. $_ — "hozirgi element" degani.

Savol: Pipeline ichida "hozirgi o'tayotgan elementni" bildiruvchi maxsus belgi qaysi?
Javob: $_ (yoki yangi versiyalarda $PSItem) — Where-Object va ForEach-Object ichida eng ko'p ishlatiladi.
10

Xatoliklarni boshqarish

try / catch / finally
 Misol
try {
    $natija = 10 / 0
} catch {
    Write-Host "Xatolik yuz berdi: $($_.Exception.Message)"
} finally {
    Write-Host "Bu qism har doim ishlaydi"
}

try ichida xato chiqishi mumkin bo'lgan kodni yozasiz, catch xato chiqqanda nima qilishni belgilaydi, finally esa — xato bo'lsa ham, bo'lmasa ham — har doim ishlaydi (masalan, faylni yopish uchun qulay).

⚠️
Ba'zi xatolar "to'xtatmaydigan" (non-terminating) bo'ladi va try/catch ularni ushlamaydi. Bunday holatda cmdlet oxiriga -ErrorAction Stop qo'shing — shunda u ham "to'xtatadigan" xatoga aylanadi.
Savol: Xato bo'lsa ham, bo'lmasa ham ishlaydigan blok qaysi?
Javob: finally — masalan faylni yopish yoki ulanishni tugatish kabi "har holda bajarilishi shart" ishlar uchun.

Skriptlar (.ps1) va Execution Policy

Buyruqlarni fayl qilib saqlash

Bir nechta buyruqni .ps1 kengaytmali faylga yozib, uni istalgan vaqt qayta ishga tushirish mumkin.

 salomlash.ps1
param(
    [string]$Ism = "Mehmon"
)
Write-Host "Salom, $Ism! Skript ishga tushdi."
 Ishga tushirish
PS C:\> .\salomlash.ps1 -Ism "Jasur"
Salom, Jasur! Skript ishga tushdi.
⚠️
Execution Policy — Windows standart holatda tashqi skriptlarni xavfsizlik uchun bloklaydi ("running scripts is disabled" xatosi). Faqat o'zingiz yozgan/ishonchli skriptlar uchun admin PowerShell'da: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser. Internetdan olingan noma'lum skriptlarni ishga tushirishdan oldin har doim ichini o'qib chiqing.
Savol: "running scripts is disabled on this system" xatosini qanday qoidaga mos tarzda hal qilish mumkin?
Javob: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser buyrug'ini admin huquqida bir marta ishga tushirish — bu faqat joriy foydalanuvchi uchun, mahalliy skriptlarga ruxsat beradi, internetdan yuklangan imzosiz skriptlarni esa hali ham ogohlantiradi.

Modullar va PowerShell Gallery

Tayyor vositalardan foydalanish

Modul — boshqa odamlar yozgan, qayta ishlatsa bo'ladigan cmdlet to'plami. Rasmiy ombor — PowerShell Gallery.

 Misol
PS C:\> Find-Module -Name "*Az*"          # qidirish
PS C:\> Install-Module -Name Az -Scope CurrentUser
PS C:\> Import-Module Az
PS C:\> Get-Module -ListAvailable         # o'rnatilgan modullar ro'yxati
Savol: Modulni o'rnatgandan keyin, uning cmdletlaridan foydalanish uchun avval nima qilish kerak bo'lishi mumkin?
Javob: Import-Module ModulNomi — ko'pincha avtomatik yuklanadi, lekin ba'zan qo'lda chaqirish kerak bo'ladi.

Tizim bilan ishlash

Jarayon, xizmat va kompyuter ma'lumotlari
 Foydali buyruqlar
PS C:\> Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
PS C:\> Get-Service | Where-Object { $_.Status -eq "Running" }
PS C:\> Stop-Process -Name "notepad" -Force
PS C:\> Get-ComputerInfo | Select-Object OsName, OsVersion, CsTotalPhysicalMemory
PS C:\> Get-Disk | Select-Object Number, FriendlyName, Size
ℹ️
Jarayon yoki xizmatni to'xtatish, o'rnatish o'zgartirish kabi amallar ko'pincha administrator huquqi (PowerShell'ni "Run as Administrator" orqali ochish) talab qiladi.
Savol: Faqat "ishga tushirilgan" (Running) xizmatlarni ko'rish uchun qanday buyruq yozasiz?
Javob: Get-Service | Where-Object { $_.Status -eq "Running" }

Tarmoq — Web va REST so'rovlari

Internetdan ma'lumot olish
 Misol
PS C:\> Test-Connection google.com -Count 2
PS C:\> Invoke-WebRequest -Uri "https://example.com" -OutFile "sahifa.html"
PS C:\> $javob = Invoke-RestMethod -Uri "https://api.example.com/data"

Savol: JSON qaytaruvchi API bilan ishlashda qaysi cmdlet qulayroq?
Javob: Invoke-RestMethod — u JSON javobni avtomatik PowerShell obyektiga aylantirib beradi, qo'shimcha ConvertFrom-Json kerak bo'lmaydi.
16

Remoting asoslari

Boshqa kompyuterda buyruq bajarish (umumiy tushuncha)

PowerShell Remoting orqali o'zingizga ruxsat berilgan boshqa kompyuterda buyruq bajarish mumkin. Bu — tarmoq administratorlari uchun kundalik vosita, lekin faqat o'zingizga tegishli yoki ruxsat olingan kompyuterlarda ishlatiladi.

 Misol (tushuncha uchun)
PS C:\> Enter-PSSession -ComputerName "ISH-KOMPYUTER" -Credential (Get-Credential)
PS C:\> Invoke-Command -ComputerName "SERVER1" -ScriptBlock { Get-Service }
⚠️
Remoting ishlashi uchun maqsad kompyuterda Enable-PSRemoting oldindan yoqilgan va tarmoq siyosati ruxsat bergan bo'lishi kerak. Bu — faqat o'zingiz boshqaradigan yoki ruxsat olingan kompyuterlarda qonuniy ishlatiladigan funksiya.
Savol: Bir buyruqni (masalan Get-Service) bir nechta masofaviy kompyuterda bir vaqtda bajarish uchun qaysi cmdlet qulay?
Javob: Invoke-Command -ComputerName @("PC1","PC2") -ScriptBlock { Get-Service } — bir nechta kompyuter nomini ro'yxat qilib berish mumkin.

Profil fayli va alias

PowerShell'ni o'zingizga moslash

$PROFILE — PowerShell har safar ochilganda avtomatik ishga tushadigan skript fayli. Shu yerga tez-tez ishlatadigan sozlamalar, funksiyalar yoki aliaslarni yozib qo'yish mumkin.

 Misol
PS C:\> $PROFILE                      # fayl manzilini ko'rsatadi
PS C:\> if (!(Test-Path $PROFILE)) { New-Item -ItemType File -Path $PROFILE -Force }
PS C:\> notepad $PROFILE               # tahrirlash uchun ochish
# profil faylga qo'shing:
Set-Alias ll Get-ChildItem
function Desktop { Set-Location "$HOME\Desktop" }
Savol: PowerShell har safar ochilganda avtomatik ishga tushadigan fayl qanday o'zgaruvchi orqali topiladi?
Javob: $PROFILE

Amaliy mini-loyihalar

O'rganganlaringizni birlashtiring

1) Papkadagi fayllarni turi bo'yicha hisoblash:

 fayl-hisob.ps1
Get-ChildItem -Path "." -File |
    Group-Object Extension |
    Sort-Object Count -Descending |
    Select-Object Name, Count

2) Fayllarni sanaga qarab ommaviy nomlash:

 nomlash.ps1
Get-ChildItem -Filter *.jpg | ForEach-Object {
    $yangiNom = (Get-Date -Format "yyyy-MM-dd") + "_" + $_.Name
    Rename-Item $_.FullName -NewName $yangiNom
}

3) Eski fayllarni avtomatik topish (30 kundan eski):

 eski-fayllar.ps1
$chegara = (Get-Date).AddDays(-30)
Get-ChildItem -Recurse | Where-Object { $_.LastWriteTime -lt $chegara } |
    Select-Object FullName, LastWriteTime
💡
Har bir misolni avval -WhatIf bilan yoki natijani faqat Select-Object bilan ko'rib, keyin haqiqiy amalni (masalan Rename-Item yoki Remove-Item) bajaring.
